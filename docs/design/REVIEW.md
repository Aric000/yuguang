# 设计与原生验收

采用 design-taste-frontend 的应用界面规则。抽取方向：Framed sheet，seed 476280743；无重抽。
保留已确认的 macOS 系统字体、雾白与炭黑配色。原生 400 pt 小窗口不需要侧栏，采用无侧栏的浅色外框 + 8 pt 内缩工作面；原生设置按窄屏规则垂直排列。

产品的形状来自“一行里看见比赛”：短横线与直播信号点为图标，固定比分与可替换文字组成单行窗口。
绿色仅出现在直播状态；数字使用系统等宽数字；全局隐藏没有过渡动画。

## 每个页面的问题

- 赛程：我关注的球队现在有哪些比赛？日期、球队筛选和可点击赛程行。
- 直播：比分如何，刚刚发生了什么？比分优先，随后是最新文字。
- 单行：不离开当前工作，能否扫一眼？固定比分、截断文字、展开入口。
- 设置：如何控制出现方式？快捷键、主题、置顶与菜单栏选项。

## 视觉检查

截图由真实 NSHostingView 缓存原生 SwiftUI 视图产生，位于 `docs/screenshots`。这是原生应用，没有 HTML DOM，因此未声称通过面向网页的 inspect.mjs / 浏览器 1440、768、390 检查。

第一轮检查了 live-light、live-dark、settings、compact。修复设置开关未对齐到右边缘的问题；第二轮重新生成并逐一查看四张截图：

- 比分是最大数字；两侧球队与比分顺序一致。
- 正文统一左边界、相同内边距，没有文字覆盖。
- 浅色以明暗层级区分、深色为中性黑，无背景渐变和玻璃。
- 单行实际高 32 pt；长文尾部截断，展开操作保持可见。
- 设置页可以滚动，所有开关右对齐。底部产品说明需滚动阅读，是设置页的正常布局。
- 只有演示模式使用示例数据，正常模式走实时网络。演示标记同时在标题和状态栏显示。

自评（图片人工判断）：层级 8/10、可读性 8/10、密度 8/10、产品辨识度 7/10。
不足：图标很克制，未来可继续微调；窄窗口优先比分和最新文字，不展示全套球员统计。
无外部图片素材，无需图库版权署名；应用图标由 scripts/make-icon.swift 原创绘制。

## 技术验证

本机 release 编译通过（Swift 编译警告按错误处理）。Command Line Tools 的链接器会报告其默认搜索目录不存在，但实际链接成功。
9 项 Swift Testing 数据协议测试通过。真实接口验证拿到 10 天 / 73 场赛程、一场进行中的比赛详情和 31 条近期文字；这些数字是验收时的接口结果，随后会变化。

8 项原生窗口检查通过：Carbon 全局快捷键注册、展开可见、32 pt 单行、即时隐藏、恢复位置和形态、重新展开、取消置顶、恢复置顶。
桌面 UI 实际打开了当天赛程、进入进行中的比赛，读到真实比分和文字，并成功切为单行。桌面自动化在持续更新期间偶发超时或“用户已更改应用”提示，因此全局按键触发的隐藏结果没有仅凭 AX 文本宣称验证；隐藏 / 恢复状态另由上述原生窗口检查断言。
网页专用 lint.mjs 不支持 Swift 文件，返回“无支持的源文件”；这没有被当作通过检查。

## 单行鼠标移出透明

单行鼠标离开时清除背景、窗口阴影、分隔线与操作按钮，文字与排版宽度不变；鼠标进入整个单行区域时恢复。通过本地与全局鼠标移动监听，以窗口矩形判断移入移出；监听返回原事件，不吞掉点击或拖动。这样即使完全透明区域的鼠标事件交给下层应用，也能恢复背景。仅监听鼠标移动，不监听键盘输入。正常展开窗口不随鼠标透明。
本轮 release 编译与 11 项原生窗口检查通过，新增检查移出透明与无阴影、移入恢复、展开后不受悬停影响。已查看 compact.png 与 compact-text-only.png 两种原生截图。
桌面交互已确认：鼠标进入单行区域时拖动柄、展开按钮和背景恢复；切到另一个应用后再次透明，AX 操作按钮随之消失。透明截图空白处 alpha 为 0，非用桌面颜色模拟背景。
