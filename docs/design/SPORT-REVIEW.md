# 运动风格升级验收

## 方向与内容

沿用 Framed sheet，新的设计记录 seed 730602018。保留原生 SwiftUI / AppKit 与 macOS 系统字体，未更换技术栈。外框、白色工作面、8 pt 内缩仍保留。用户明确要求球队 Logo 和球队色，因此队徽中的多色、湖人紫色与对应球队色属于真实品牌素材；正文与导航仍以中性灰为主。

理念：两队的身份成为比分牌的结构；单行是安静的文字条，展开后是具备球队身份的比赛窗口。

数据：双方名称、队徽 URL、昼夜配色、比分和赛事阶段来自赛程 / 比赛接口。30 个队徽打包以便离线即时显示；来源链接逐个保存在 `Sources/Yuguang/Resources/Teams/catalog.json`。这些是球队标识，权利归相应权利人，不虚构开放版权许可。
四款应用 Logo 是原创向量，待用户定稿；设置可预览，不提前替用户选定正式图标。

## Before / after

Before 原生截图保存在 `before-sport/`。之前是文字队名、一个中心比分、无球队身份。现在是对应的两侧队徽、两侧比分、球队浅色背景与 3 pt 色线；赛程行同时显示两队 Logo、队名与各自比分。
去掉了单行左侧拖动标记，并在文字和空白区加原生拖动表面。右侧留出 40 pt 保持展开按钮可点击，双击仍展开。

原生程序不能接受网页 DOM inspector 检查，未声明 inspect.mjs 0 FAIL；改用原生截图与实际交互。没有使用照片、视频或图库图案。

## 图片人工检查

已查看浅色、深色、赛程、设置、360 pt 窄窗口、620 pt 宽窗口、单行有背景与透明等截图。第一轮发现 Logo 选择挤占设置主操作，改成小型预览与下拉选择；其余布局边界完整、比分没有压缩到队名上。

- 重点：比分最大，真实队徽提供两侧锚点；球队名称、比分及主客顺序一致。
- 边界：内边距对齐；窄窗口没有文字相互覆盖，宽窗口维持对称。
- 色彩：中性背景，球队色只用于身份与比分牌色线，无渐变或玻璃效果。
- 状态：零分、无分数、未开赛、结束、直播与加载错误继续使用原有数据逻辑。
- 单行：无左侧图标，文字没有引入队徽；移出仍透明，移入仍恢复操作。
- 示例：带“演示”标记的湖人 102 / 勇士 99 等均为验收样本，不作为真实赛事事实；正常运行仍调用网络数据。

自评：层级 8/10，品牌识别 8/10，可读性 8/10，密度 7.5/10。400 pt 默认窗口优先展示比分牌与最新两三条文字；更多历史通过滚动阅读。Logo 最终选择留给用户。
