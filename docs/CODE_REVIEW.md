# 双原生客户端自审

日期：2026-10-21。范围：恢复的 SwiftUI/AppKit Mac 客户端、新增 C#/WPF Windows 客户端、共享资产、CI 与安装包脚本。由实现者自审，不冒充独立第三方审查。

目标：保留 Mac 原生排版，提供 Windows 原生实现，验证关键窗口交互、数据正确性与可复现打包。

## 已检查和修复

- **P1 · 过期响应污染比赛**：Windows 选择比赛时取消旧请求并增加代次，所有网络返回写入状态前都校验当前代次。测试使用故意忽略取消的旧请求，确认新比赛和文字不会被覆盖。Mac 保留已有取消与代次保护。
- **P1 · 大整数比赛 ID 与比分方向**：直接保留 ID 十进制表示，不经浮点数；比分统一为客队在左、主队在右，缺失值不伪造 0，未开赛显示 vs。测试包含超过 2^53 的 ID、真实 0 分与缺失分数。
- **P1 · 窗口拖动与精简高度**：Mac 保留原生 DragView；Windows 使用 WPF 无边框透明窗口及 DragMove，交互按钮、选择框、调整尺寸控件不触发拖动；支持 32–192 逻辑单位的 1–6 行窗口。Windows 的实际运行检查由 Windows Runner 执行。
- **P2 · 快捷键冲突**：Windows 新组合注册成功后才释放旧组合；失败提示且保留旧绑定。默认使用 Ctrl + OEM_3，与键盘上的反引号键对应。
- **P2 · 偏好和诊断隔离**：损坏的偏好文件回退默认值；参数归一化；写入采用临时文件替换。显式 demo 诊断不写入用户偏好。窗口模式分别保存位置与尺寸。
- **P2 · 高 DPI 透明命中**：鼠标和窗口边界均使用设备像素进行比较，避免直接将屏幕像素与 WPF DIP 混用。位置恢复按当前显示器工作区限制。
- **P2 · 构建迁移残留**：删除 Electron 源码与旧 Node 工作流，主线只构建两个原生客户端；Mac 编译前从 shared/assets 同步资源，避免维护重复图标。

- **P2 · 刷新打断控件操作**：WPF 轮询更新会重建视图；鼠标被下拉框、弹出菜单或调整尺寸操作捕获期间延迟重建，释放后再刷新，保留当前操作。

## 验证记录

- Mac：11 项 Swift Testing 核心测试；22 项原生窗口诊断，包括真实拖动区域、快捷键、菜单图标、球队资源、行数、透明状态、比赛切换、显示隐藏和简洁模式。
- Windows 核心：19 项离线检查，另有可选真实赛程、比分、直播 key 与文字接口检查；在本机 .NET 10 执行。
- WPF：Mac 上以 Windows 目标交叉编译，编译警告作为错误；GitHub Windows Runner 已通过 45 项 WPF 窗口检查并构建自包含便携 EXE 与当前用户安装程序；便携版启动、静默安装后启动及卸载检查均已在 Windows Runner 通过。
- Mac 打包：DMG 与 ZIP；应用使用 adhoc 签名，并以 codesign --verify --deep --strict 校验。

## 审查结论与范围

已处理发现的数据竞态、精度、窗口几何、快捷键与构建问题。没有以关闭检查掩盖失败。GitHub 双端构建、原生检查与安装包检查均已通过，Release 发布时再次执行相同检查。

尚无 Windows 真机的多显示器、多 DPI、系统主题人工验收；自动诊断不替代这一范围。两端均未配置商业代码签名，Mac 未经 Apple 公证。第三方赛事接口可变，API 联通检查保留为手动诊断，不将外部网络波动作为离线测试失败。
