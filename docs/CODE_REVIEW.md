# 代码审查记录

日期：2026-10-21。范围：当前原生 macOS 客户端的赛事接入、状态轮询、窗口与菜单栏、快捷键、构建与测试脚本。

目标：确认完整窗口无法拖动的原因，检查切换比赛、错误处理与偏好保存，并为首次提交整理可复现的验证记录。

## 发现与处理

### P1 · 完整窗口无法拖动（已修复）

`Application.swift` 配置了无边框 NSPanel，并启用 `isMovableByWindowBackground`，但 `Views.swift` 的标题栏由 SwiftUI hosting 承载，没有原生拖动区域。仅开启窗口属性不足以让这些内容传递拖动事件。

复现：在设置页拖动标题栏空白处，窗口的持久化位置保持 `{{667, 249}, {400, 603}}`。

修复：标题栏的 Logo、标题与剩余空白组成独立区域，覆盖复用的 AppKit `DragArea`；右侧操作按钮位于区域之外。精简视图继续使用已有拖动实现。

回归：原生检查验证标题栏命中 DragView 并实际改变窗口位置；桌面拖动将位置从 `{{667, 249}, {400, 603}}` 改为 `{{717, 229}, {400, 603}}`。设置页返回按钮仍可正常使用。

### P2 · 业务拒绝响应可能丢失具体错误信息（已修复）

`HupuAPI.decode` 原先先解码泛型 `result`，再检查 `success/status`。当拒绝响应的 result 与成功数据结构不同，解码会提前抛错，用户看不到服务端的失效提示。

修复：先解码业务状态并拒绝失败响应，再解析成功结果。新增回归用例：文字列表请求返回对象形状的错误 result 时，仍保留「直播参数已过期」。

### P2 · 原生诊断会污染日常偏好（已修复）

`--self-test` 会选择演示比赛并切换置顶等选项；`--capture` 也调整窗口形态。旧逻辑只恢复部分字段，可能留下演示比赛 ID 或测试窗口位置。

修复：诊断开始前快照相关持久化键，正常退出后恢复；自检断言失败退出时同样恢复。普通启动不走此逻辑。
